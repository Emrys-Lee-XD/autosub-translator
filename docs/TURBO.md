# Turbo 使用及实现说明

版本：0.2.0-beta.4。用于一次处理多个视频，优先减少 GPU 等待和重复模型加载。

## 使用

双击项目目录的 `start_gui.bat` 或 `start_gui.pyw`。基本设置勾选 Turbo，高级参数的音频预取默认 2。项目目录中的个人 `config.json` 保留原有设置，公开 `config.json.example` 默认关闭。

CLI 的 `--turbo`、`--no_turbo` 覆盖配置。`--audio_prefetch 1`～`4` 控制预取数量。GUI 当前值会直接传给 CLI，未保存的修改也会生效。Google Cloud Speech 保留普通处理方式，Turbo 不对 Cloud Speech 并行。

## 流程

```mermaid
flowchart LR
  A[文件列表] --> B[单路 FFmpeg 提取]
  B --> C[最多 2 个预取音频，默认值]
  C --> D[单个常驻 Whisper 进程]
  D --> E[原文 SRT 与状态落盘]
  E --> F[待翻译列表：磁盘保存原文]
  F --> G[单路所选 API 翻译与重试]
  G --> H[核验并提交最终字幕]
```

音频预取数量包含正在提取和提取完成的后续文件，排除当前识别文件。提取只开一路，避免多路 FFmpeg 抢占 CPU、磁盘。识别只开一个进程和一个模型实例，多个任务依次复用；每个文件的结果、语言检测、过滤计数及进度独立。Gemini 和自定义 OpenAI 兼容 API 共享同一翻译入口；译文请求默认仍只有一路，使用原来的条数、间隔及重试参数。

翻译队列保存任务信息，原文已写入文件；它没有阻塞 STT 的容量上限。API 变慢时，STT 继续处理后续音频。识别完成的 WAV 在原文及状态提交后立即删除，勾选“保留临时工作区”则保留。所有可能继续识别的文件处理完毕后，模型进程退出并释放显存，翻译可以继续。

CPU 预处理、磁盘、识别内部 VAD 和设备传输仍会影响 GPU 利用率。Turbo 不能保证 GPU 恒定 100%，提取慢于识别时仍可能等待，长视频的提取也可能成为新瓶颈。

## 停止与恢复

点击“安全停止”后，不再启动新的提取、识别或翻译阶段。已经运行的阶段完成后提交各自结果，因此可能保留部分“等待识别”的 WAV 和“等待翻译”的原文。再次处理相同目录，会验证身份并从已完成阶段继续。

已识别原文不会因切换 Turbo、普通模式或预取数量而失效。修改视频、识别配置、原文内容或翻译配置仍会按原有身份规则重新核验。输入视频中途被替换、原文在翻译期间被修改时，成品提交会失败，保留现有文件。

状态使用素材目录的 `.autosub_state.json`；原有日志和检查点继续沿用。额外的 `.autosub_turbo_metrics.json` 记录本次加载次数、阶段耗时、调度间隔及完成数量。该文件含本机路径，和其他任务内部文件一样不进入源码发布包。

音频恢复既验证 PCM WAV 格式和长度，也需要已提交状态或提取成功标记。单独存在的有效 WAV 不能证明 FFmpeg 正常完成。识别临时 SRT、翻译临时 SRT 和移动后未完成的状态提交均有对应恢复检查；身份未知的外部字幕继续保留并报错。

## 错误处理

| 情况 | 行为 |
|---|---|
| 单个视频提取、识别或译文核验失败 | 记录失败，继续其他可处理文件 |
| 模型初始化、设备配置失败 | 暂停识别，不反复加载；已准备的原文仍可翻译 |
| 识别进程异常退出 | 当前文件最多重试一次；整批最多重启两次 |
| 本地识别超时 | 终止该识别进程，不提交未完成原文；默认 0 不限时 |
| 翻译超时或临时 API 错误 | 保留原文及检查点，沿用现有重试/超时机制 |
| 翻译最终返回 400/401/403/404/429 | 暂停后续翻译请求，STT 继续；修正配置或配额后重新启动 |
| 空闲磁盘小于 512 MiB 或提取报告磁盘已满 | 暂停新的提取；已准备音频和原文可以继续处理 |
| 状态或最终提交写盘失败 | 停止调度并保留恢复文件 |
| Windows GUI/主进程异常退出 | Job Object 随进程关闭，清理其子进程；识别进程另有输入管道关闭保护 |

安全停止会等待当前翻译文件的请求与重试完成，最迟受该文件的翻译超时限制；它不是立即中断。强制结束后续跑需重新加载模型。初始化上限 20 分钟用于首次下载或模型加载，超时后暂停识别。

## 开发结构

| 文件 | 责任 |
|---|---|
| `stt_engine.py` | 创建模型，单文件识别；普通和 Turbo 共享相同推理参数 |
| `stt_worker.py` | 常驻进程，版本化 JSON Lines 命令及结果协议；先加载原生库，再启动输入线程 |
| `stt_client.py` | 进程控制、读取协议及日志、进程代次与任务尝试标识 |
| `pipeline_job.py` | 可恢复的提取、识别提交、翻译提交与清理；每个任务冻结参数 |
| `turbo_scheduler.py` | 单路提取/翻译线程、音频预取、持续喂给 STT、状态与进度调度 |
| `task_state.py` | 限制状态/日志写入到调度线程，合并并原子保存状态 |
| `process_utils.py` | 超时、子进程树生命周期及错误码、Key 脱敏 |
| `pipeline.py` | 普通顺序模式的同一套阶段调用 |

工作线程和 GPU 进程返回事件，调度线程统一更新状态。进程代次和每次识别的 attempt 防止旧进程结果误提交；进度合并、日志队列有上限，最终结果事件不会丢弃。目录锁、同名输出冲突检查和工作区所有权标记继续使用原有机制。

当前范围是文件级流水线，不包括同一长视频切块并行、多个 GPU 模型或自动增加 API 请求并发。合并后的验证见 [版本验证记录](VALIDATION.md)；早期独立 Turbo 的历史证据见 [2026-10-07 记录](TURBO_VALIDATION_20261007.md)。
